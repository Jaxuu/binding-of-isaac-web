# ADR-003 · 固定时间步循环 + 可种子化 PRNG

- **状态**：已采纳（Accepted）
- **日期**：2025-09-27
- **决策者**：程基岩（技术总监）
- **关联需求**：用户需求 #3（随机地牢生成）、任务书「每个 Iteration 自测」、GDD 01-dungeon 的 6 条不变量

---

## 1. 上下文（Context）

两个强约束来自任务与设计：

1. **手感帧率无关**：以撒的核心手感是「眼泪的飞行速度、敌人的追击速度、受击硬直」——这些必须是**时间**的函数，不能随显示器刷新率（60/120/144Hz）变化，否则在 144Hz 屏幕上敌人会变快。
2. **可复现 + 可测试**：任务书要求每个 Iteration 用无头浏览器自测、截图、检查。若随机不可复现，就无法断言「这个种子一定生成 5–8 房、Boss 一定最深」。GDD 01-dungeon 明确了 **I1–I6 六条不变量**必须被验证。

## 2. 备选方案（Alternatives）

### 2.1 循环

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **固定时间步 + 累加器（选中）** | 逻辑帧率无关、可复现、手感稳定；物理/碰撞简单（无穿透） | 需处理「螺旋死亡」与追帧上限 | ✅ **采纳** |
| 可变 dt（每帧 `dt = now - last`） | 实现最简单 | 手感随帧率漂移；快速移动的子弹在低帧率下穿透；难复现 | ❌ 违反手感要求 |
| 固定步 + 渲染插值 | 视觉更平滑 | 对像素风俯视 2D 无收益，徒增复杂度与状态 | ❌ 收益错配 |

### 2.2 随机

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **mulberry32 + FNV-1a 字符串散列（选中）** | 纯 JS、极短、质量足够、可种子化、零依赖 | 非密码学安全（本作不需要） | ✅ **采纳** |
| `Math.random()` | 现成 | 不可复现 → 无法测地牢不变量 | ❌ |
| 引第三方 PRNG（seedrandom） | 成熟 | 违反「零依赖」 | ❌ 违约 |

## 3. 决定（Decision）

**循环（`src/core/loop.js`）**

- 逻辑固定步：`FIXED_DT = 1/60`（60Hz）。
- 渲染跟随 `requestAnimationFrame`，渲染最新状态（不插值）。
- 累加器上限 `MAX_STEPS = 5`：单帧最多跑 5 个逻辑步，防止切后台回来「追帧」卡死。
- 单帧 `dt` 硬上限 `MAX_FRAME_DT = 0.25s`：长时间挂起后不产生巨大跳变（避免子弹瞬移穿过敌人）。
- 内建 FPS / frameMs / updateMs / renderMs 遥测，供 `F3` 调试显示。

**随机（`src/core/rng.js`）**

- 核心：**mulberry32**（32 位状态、极快、分布良好）。
- 种子：接受 `number` 或 `string`；字符串经 **FNV-1a** 散列成 uint32；`0` / 空 → 用时间戳。
- `Rng` 类提供语义化 API：`float/int/chance/pick/weighted/shuffle/range/fork`。
- **`fork()`**：派生独立子流（如「房间内容」用主种子的 fork），保证「改一个房间的内容」不扰动其它房间的生成序列。
- 所有生成器（地牢 / 房间内容 / 道具掉落）**必须接受注入的 `Rng`**，不得直接调用 `Math.random()`。

**唯一允许 `Math.random()` 的地方**：纯视觉抖动（如震屏偏移 `shakeX/Y`、粒子角度噪声）——这些不影响可复现的玩法状态。

## 4. 后果（Consequences）

### 正面
- 手感在任何刷新率下一致。
- 地牢生成 100% 可复现：`generateDungeon(seed)` 在 Node 与浏览器结果一致 → 不变量可单测（实测 500 种子 0 失败，60 种子浏览器内验证 0 失败）。
- `?seed=777` 可复现同一局，方便评审与 bug 复现。
- 追帧上限保护了「切后台/卡顿」的极端情况。

### 负面 / 代价
- 固定 60Hz 逻辑在 144Hz 上会有「同一逻辑帧渲染两次/三次」，视觉上无插值会有极轻微的步进感——像素风下不可见。
- 需自律：任何新的随机都要走 `Rng`，否则破坏可复现性。

### 缓解
- 在 `rng.js` 顶部与 `architecture.md` 明确「玩法随机必须走 Rng」的规约（见控制清单）。
- 地牢不变量测试作为守门（CI 级别的 `node tests/run-tests.mjs`）。

## 5. 验证方式（Verification）

- `tests/run-tests.mjs`：mulberry32 分布/确定性、FNV-1a 散列稳定、`fork` 独立、`weighted` 边界。
- 地牢不变量 I1–I6：**500 种子 0 失败**（`dungeon.js` 单测）。
- 浏览器内 60 种子：`bad: 0, countMin: 5, countMax: 8`（`tests/last-run-dungeon.json`）。
- `tests/harness.mjs` 启动后 `fps ≈ 60`，无 JS 错误。

## 6. 知识缺口

无。mulberry32 / FNV-1a 为公开算法，`requestAnimationFrame` 为稳定标准 API。
