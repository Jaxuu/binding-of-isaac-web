## 1. 待机态 alpha 裁定：`0.42`

### 依据（按 art-bible 对比度原则推导，不是拍脑袋）

摇杆叠在**最亮的地砖** `floorTreasure #5b5343`（宝箱房）上时最容易被"吃掉"。要求摇杆边缘（`ring`）与该底色的**感知对比 ≥ 可分辨下限**。

- 底衬基准亮度：`#5b5343` 相对亮度 L ≈ **0.087**
- 待机态最亮元素 = ring 白 `#ffffff`（L=1.0），按 alpha 合成：`合成L ≈ 0.087 + α·(1.0−0.087)`
- 要求合成亮度达到"明显可辨"（约 L≥0.35，即目视清晰的浅灰描边）：

```
α ≥ (0.35 − 0.087) / (1.0 − 0.087) ≈ 0.29   → 绝对下限
```

- 但**待机态不能太抢眼**（不能干扰战斗画面主体）。取"清晰可辨但视觉退让"的区间：**0.38–0.46**。
- 折中取 **0.42**：高于绝对下限 45%，且明显低于激活态（1.0），两态差 >2×，肉眼一眼可辨。

### 为什么不用 0.45（team-lead 初值）
0.45 与 0.42 差异在肉眼阈值边缘，**没有本质区别**；我取 0.42 是因为它给"激活态=1.0"留出更明确的 2.4× 层级差，且正好落在 §3 底衬叠加后仍能区分待机/激活的甜点区。**team-lead 的 0.45 完全可用，若已写死可不动**——这属于 5% 内的微调，不值得为此改代码。

### 缓动目标修正（关键）
当前 `update()` 的缓动终点是 0（消失态）。需改为：

```
待机 alpha 目标 = 0.42（非 0）
激活 alpha 目标 = 1.0
出现快（18/s）、消失慢（7/s）的速率保持不变
```

即 `alphaMove/alphaFire` 在**未激活时的收敛终点是 0.42，激活时是 1.0**，而不是 0/1。

## 2. 待机态 vs 激活态：明确规则

### 规则
> **待机态 = 底盘（base）+ 外圈（ring）+ 十字刻度，且 alpha=0.42；不绘制摇杆头（knob）与图标。**
> **激活态 = 待机态全要素 + 摇杆头（按手指偏移）+ 图标，alpha=1.0。**

### 为什么（判断理由）

1. **避免与游戏内实体混淆**：以撒房间里全是圆形实体（眼泪、敌人、心、金币）。常驻画一个实心"摇杆头"会被误认为是**场景里的可拾取物或敌人**。底盘只有描边环，是"界面框架"语言；摇杆头是实心圆，是"物体"语言——**待机态不画头，就从视觉语法上排除了误认**。
2. **归位即空闲**：激活时手指偏移摇杆头 → 玩家一眼看到"我正滑向哪"。待机时没有输入方向，画一个"居中静止的头"反而让人怀疑它是不是卡住了。
3. **降低常态视觉噪声**：战斗画面已有子弹/粒子大量动态元素，待机摇杆应静默存在。少画一个实心头，常态画面更干净。
4. **可访问性**：待机态弱化、激活态强化的两态差，让"我现在按着哪个摇杆"这件事靠**亮度/元素数量双通道**表达，符合 accessibility.md「不靠颜色单通道」原则。

### 补充细节
- **十字刻度**：待机/激活都画，但待机态刻度 alpha = `0.42×0.4 = 0.168`（沿用现有 `alpha*0.4`）；激活态 = `1.0×0.4 = 0.4`。保留即可，无需改。
- **移动摇杆激活时**：现有"四向箭头"图标保留在 knob 上。
- **射击摇杆激活时**：现有"准心"图标保留在 knob 上。

## 3. 可读性：加一层暗色底衬（唯一配色改动）

### 问题确认
当前 `baseColor` alpha 仅 **0.16 / 0.18**，`ring` alpha 0.35–0.4。

- 在**暗色地砖** `#3a2b26`（L≈0.028）上：0.16 的底几乎不可见，但 ring 0.35 白尚可辨 → **勉强看清**。
- 在**亮色地砖** `floorTreasure #5b5343`（L≈0.087，实际宝箱房还有金色 overlay 会更亮）上：0.16 暖白底 = 肉眼几乎不可见，ring 0.35 白对比不足 → **看不清**。

结论：**暗底勉强、亮底不行**。需要兜底。

### 兜底方案（选用：加暗色底衬圆）
不用提高 ring 亮度（那会过度抢眼），而是**在底盘下方垫一层暗色实心圆**，把背景统一压暗，让 ring 在暗底上稳定可读：

| 层 | 内容 | 颜色 | 说明 |
|---|---|---|---|
| 1（最底） | **暗色底衬圆** r = maxR + 4 | `rgba(10,8,8,0.34)` | **新增**。垫底，弱化背景地砖 |
| 2 | 底盘 base 圆 r = maxR | 待机/激活见色表 | 原有 |
| 3 | 外圈 ring 描边 3px | 见色表 | 原有 |
| 4 | 十字刻度 | 见色表 | 原有 |
| 5（激活时） | 摇杆头 knob r22 | 见色表 | 仅激活 |
| 6（激活时） | 图标 | 见色表 | 仅激活 |

> 底衬 alpha `0.34` 的依据：足以把最亮地砖 `#5b5343` 压到 L≈0.06 以下（等效暗格亮度），同时不遮挡地砖纹理（<0.5 不糊）。

### 最终色值表（可直接抄进代码）

| 元素 | 移动摇杆（左） | 射击摇杆（右） |
|---|---|---|
| 暗色底衬（新增，2 态都画） | `rgba(10,8,8,0.34)` | `rgba(10,8,8,0.34)` |
| 底盘 base — 待机(α0.42) | `rgba(240,230,210,0.16)` | `rgba(220,90,70,0.18)` |
| 底盘 base — 激活(α1.0) | `rgba(240,230,210,0.16)` | `rgba(220,90,70,0.18)` |
| 外圈 ring 描边 3px | `rgba(255,255,255,0.42)` | `rgba(255,180,150,0.5)` |
| 十字刻度 2px（×0.4） | 同 ring | 同 ring |
| 摇杆头 knob r22（**仅激活**） | `rgba(240,230,210,0.62)` | `rgba(230,110,80,0.68)` |
| knob 描边 3px | `rgba(255,255,255,0.6)` | `rgba(255,190,160,0.65)` |
| knob 阴影 | `rgba(0,0,0,0.4)` blur8 | 同 |
| 图标（**仅激活**）· 移动=四向箭头 | `rgba(255,255,255,0.8)` | — |
| 图标 · 射击=准心 | — | `rgba(255,220,200,0.9)` |

> **alpha 列由缓动控制**，色值里的数字是"处于该态时的最终观感值"。实现上：把 §1 的 `alpha` 作为 `globalAlpha`，色值本身用上表的**不透明基准**，两态差异由 `globalAlpha` + "是否画 knob"共同体现。
> 简化写法（推荐给程工）：把上表色值写死，用 `ctx.globalAlpha = alpha`（待机 0.42 / 激活 1.0）统一控制；`if (stick.active) { 画 knob 和图标 }`。

**色相不变的理由**：暖白（左/移动）vs 橙红（右/射击）是**功能编码**——玩家不可能把左手和右手摇杆搞混。保留。

## 4. 布局：窄视口必须自适应

### 冲突实测（基于当前代码参数）

**420×860 竖屏**，摇杆位 `(0.16W, 0.78H)`、r52：

| 元素 | 占地 |
|---|---|
| 移动摇杆（含 knob 可达） | x[-7,141] y[597,745] |
| 属性条面板（`drawStatBars`：panelH=87，y=H-133） | x[8,134] **y[727,814]** |
| Boss 血条（`by=H-58`，宽 min(460,252)） | x[84,336] y[799,821] |

**结论：确有冲突**
- 移动摇杆下沿 745 越过属性条面板上沿 727 → **竖向重叠 18px**，且横向 x 重叠段 [8,134]∩[-7,141] 完全重合 → **移动摇杆压住属性条**。
- 摇杆与 Boss 血条：竖向不重叠（745 < 799），**不冲突**（因血条居中、摇杆偏两侧）。
- 射击摇杆 x[279,427] 与 Boss 血条 x[84,336] 有横向重叠段 [279,336]，但竖向 745<799 不重叠 → **不冲突**。

**860×420 横屏**，摇杆 y[254,402]：
- Boss 血条 y[359,381] 居中 x[200,660]。移动摇杆 x[64,212] → 横向重叠 [200,212]，竖向 [359,381] 落在摇杆区间内 → **轻微压角**。射击摇杆 x[648,796] → 横向重叠 [648,660] 同理。
- 属性条面板 y[287,374] x[8,134] 与移动摇杆 x[64,212] y[254,402] → **明显重叠**。

**结论：横屏同样冲突**，且横屏可用高度更小，问题更严重。

### 裁定：窄视口自适应规则

> **规则：摇杆半径与纵向位置随视口高度自适应；横向位置保持 0.16W / 0.84W 不变。**

```js
// 建议实现（程工参考）
const stickR   = H < 560 ? 42 : 52;          // 矮视口缩小半径
const stickY   = H < 560 ? H * 0.72 : H * 0.78; // 矮视口上移
// 横向不变：move = W*0.16, fire = W*0.84
// 但需保证摇杆不越出屏幕：ox = clamp(W*0.16, stickR+6, ...) ；右侧同理
```

**为什么半径 42**：r52 在 420 宽下两摇杆中心距 = 0.68W = 286px，两个 r52 相加 104 + 各留边 → 其实不挤；真正的问题是**纵向**。缩到 42 主要是给底部 HUD 让出纵向空间（同时视觉上小手更易按准大盘，42 仍 > 拇指最小热区）。

**为什么上移到 0.72H**：把摇杆下沿从 745 提到约 671（420×860 时 `0.72×860=619`, +42+22=683），远离属性条面板上沿（727），留出 ~44px 安全间隙。

### 推荐坐标表（可直接用）

| 视口 | 摇杆半径 | 纵向位置 | 移动摇杆中心 | 射击摇杆中心 |
|---|---|---|---|---|
| **420×860 竖屏（窄）** | **42px** | **0.72H** | (67, 619) | (353, 619) |
| **≥560 高竖屏** | 52px | 0.78H | (0.16W, 0.78H) | (0.84W, 0.78H) |
| **860×420 横屏** | **42px** | **0.72H** | (138, 302) | (722, 302) |

> 横屏 860×420：`stickY = 0.72×420 = 302`，摇杆下沿 302+42+22=366，仍略压 Boss 血条上沿 359。
> **横屏额外规则**：若 `H < 520`，把摇杆**再上移到 `H*0.66`**（302→277），下沿 341 < 359，避开血条；或把 Boss 血条在横屏下移到底部 `H-30`。**推荐后者**（血条贴底更像原作，且不挤压操作区）。

### HUD 安全区总结（给程工的排版红线）

- **摇杆安全区**：底部中央 `y > H-140` 且 `|x - W/2| < W*0.2` 的区域**不放 HUD**（给摇杆留白）。
- **属性条面板**：窄视口建议**改为贴左中**或**游戏中自动隐藏**（原作以撒本身不常驻属性条），避免与左下摇杆争空间。**这条建议交文策渊/程工决定**（属玩法 UI 取舍，非纯视觉）。
- **Boss 血条**：横屏/矮视口下移贴底 `H-30`，宽度保持 `min(460, W*0.6)`。

## 5. 汇总：给程工的改动清单

| # | 改动 | 位置 | 值 |
|---|---|---|---|
