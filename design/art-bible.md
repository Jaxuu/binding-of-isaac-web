# 美术圣经 · Art Bible —《以撒的结合》网页复刻版

> 项目：case-yisa · 技术栈：原生 HTML5 Canvas 2D + 原生 JS（零依赖 / 零图片素材）
> 版本：v1.0 · 作者：林绘澄（Lin Wayson）· 状态：待用户审批

---

## 0. 总纲：本项目美术的第一性原理

**所有视觉都必须由代码在运行时绘制，禁止任何外部图片素材。**

这意味着我们不是在「画一张画」，而是在**编写一组可复用的绘制函数**。因此本圣经的写法与传统美术圣经不同：

- 每个视觉元素 = 一个**绘制配方（Draw Recipe）**：尺寸（px）→ 图元拆解 → 图层顺序 → 色值 → 描边 → 动画驱动。
- 开发拿到配方即可**逐行翻译成 Canvas API 调用**，无需再问「这个大概多大」「什么颜色」。
- 配色、描边宽度、圆角半径、动画频率**全部给具体数值**，不给形容词。

**核心目标风格一句话**：*Terry Cavanagh 式的手绘怪诞可爱 —— 粗黑有机描边包住扁平脏污色块，低明度暗黑底子上的高饱和点缀，眼泪、血液、粪便构成的黑色幽默。*

## 1. 视觉身份九节（Visual Identity）

### 1.1 视觉锚点三词

| 锚点 | 英文 | 为什么是它 |
|---|---|---|
| **怪诞可爱** | **Grotesque-Cute** | 主体是圆头大眼的婴儿，但身体畸形、五官扭曲 —— 可爱与不适的张力是《以撒》的全部魅力。所有比例决策都服从这一条。 |
| **脏污手绘** | **Grimy Hand-drawn** | 3–4px 有机抖动的粗黑描边 + canvas 随机噪点，让程序生成的矢量图「看起来像人手画的」。没有这条，一切都会变成干净的几何图形，风格立刻死亡。 |
| **暗黑高对比** | **Dark High-Contrast** | 地下室水泥 + 酒红 + 暗黄构成低明度底，眼泪蓝/血红/UI 金作为高饱和点缀。暗黑不是「加黑」，是「压低底、点亮点缀」。 |

**底线**：任何资产，若同时偏离这三个锚点中两个以上，直接打回重做。

#### 「暗黑」是如何实现的（本作色彩公式）

```
暗黑 = 低明度底 (L*≈20-35，占画面 75%+)
      + 高饱和点缀 (S*≥70 且 L*≥55，占画面 ≤15%)
      + 近黑暖描边 (#1a0d0d，勾出所有形体)
      + 极少量亮色做视觉焦点（眼泪蓝、血、UI 金）
```

**禁止用纯灰 `#808080` 作任何大面积填充** —— 会让画面「塑料」。灰一律偏暖（加红/黄分量）。

### 1.3 线条语言（描边分级表）

描边是本作风格的**生命线**。所有描边用 `C_BODY_LINE = #1a0d0d`（近黑暖），绝不用纯黑 `#000`（太生硬）。

| 品类 | 描边宽度 | 说明 |
|---|---|---|
| Boss / Monstro | **5–6px** | 最大最重，压迫感 |
| 玩家以撒 | **3.5px** | 主体轮廓 |
| 普通敌人（Gaper/Horf 等） | **3px** | 与玩家同量级 |
| 小型敌人（Fly/Spider） | **2px** | 小形体需细线避免糊 |
| 道具（房间内掉落物） | **3px** | 中型 |
| 道具图标（HUD 16×16） | **1–1.5px** | 极小尺度，可省略描边只留形状 |
| 子弹（泪/刀） | **1.5–2px** | 小且快 |
| 房间结构（墙/门/岩石） | **2.5–3px** | 边界清晰 |
| 地砖缝 | **1px**（或直接不描，用色差） | 避免网格过重 |
| UI 面板 | **3px** | 金框 |

**动态缩放规则**：
- 描边宽度**随实体缩放等比缩放**：`lineWidth = baseWidth * scale`，但设下限 `max(1.2, ...)` 防止小实体的线消失。
- 屏幕缩放（DPR > 1）时，描边**不随 DPR 加成**，而是在最终 canvas 上统一 `ctx.scale(dpr, dpr)`，让描边视觉粗细一致。
- **有机抖动**：可用 3–5 点 `quadraticCurveTo` 手动制造轻微弧度，代替直线（`lineTo`），使轮廓「手绘化」。捷径：给顶点加 `±0.5px` 随机扰动（预烘焙时固定种子）。

### 1.4 形状语言

**玩家 / 角色**
- **圆头大眼**：头 ≈ 身体 1.2 倍宽，眼睛占头宽 22–28%，呈对称双圆。
- **头身比约 2.2 头身**（Q 版），四肢短小粗钝。
- 身体略呈「梨形/水滴形」（上窄下宽），无脖子。

**敌人畸变比例原则**（越强越畸变）
- 普通敌人：头身比 1.5–3 头身。
- 精英/Boss：头身比 1–1.5 头身（巨大口/巨眼挤压比例）。
- 关键：**敌人的可爱来自「圆」，恶心来自「不对称与错位」** —— 眼睛大小不一、嘴歪、多长一条腿。

**道具轮廓可读性三原则**
1. **单色剪影可辨识**：把图标填纯黑，仍能认出是什么（形状优先于细节）。
2. **一图标一主形**：16×16 内只允许一个主形状 + 最多两个附属细节。
3. **朝向统一**：所有道具图标默认「正面/侧 3-4 视角」，光源统一左上。

### 1.5 光影与质感（代码实现）

**暗角 + 局部提亮（2–3 层 radialGradient）**

房间光照配方（每帧绘制，或在房间切换时预烘焙）：

1. **底层**：地砖铺满（已预烘焙 tile）。
2. **暗角层**（`C_VIGNETTE`）：
   ```js
   const g = ctx.createRadialGradient(cx, cy, r*0.25, cx, cy, r*1.05);
   g.addColorStop(0,    'rgba(0,0,0,0)');
   g.addColorStop(0.55, 'rgba(10,6,6,0.35)');
   g.addColorStop(1,    'rgba(0,0,0,0.78)');
   ctx.fillStyle = g; ctx.fillRect(roomX, roomY, roomW, roomH);
   ```
3. **角色脚下投影**：单独一层椭圆 `rgba(0,0,0,0.30)`，半径随角色缩放，压在地砖上、角色下。
4. **局部暖光（可选）**：宝箱/道具基座上方叠一层小 radialGradient `rgba(242,193,78,0.18)`，制造「圣光」暗示。

**脏污 / 噪点（离屏 canvas 随机点）**

```js
// 预烘焙一次，全房间复用
function bakeGrime(w, h, density = 0.06, seed = 1337) {
  const oc = document.createElement('canvas'); oc.width = w; oc.height = h;
  const g = oc.getContext('2d');
  const n = Math.floor(w * h * density);
  for (let i = 0; i < n; i++) {
    const x = rand(seed+i) * w, y = rand(seed+i*7) * h;
    const a = 0.06 + rand(seed+i*13) * 0.14;
    g.fillStyle = rand(seed+i*3) < 0.6
      ? `rgba(0,0,0,${a})`          // 暗点
      : `rgba(90,70,50,${a*0.7})`;  // 暖污点
    g.fillRect(x|0, y|0, 1 + (rand(seed+i*5)<0.2?1:0), 1);
  }
  return oc; // 叠在地板/墙上，globalAlpha≈1
}
```
- 噪点密度：地板 `0.05–0.08`，墙 `0.03–0.05`。
- 噪点应**预烘焙到静态层**，不进每帧循环。

**质感分层总结**：扁平填充 → 1 层方向性渐变（光从上/左来）→ 描边 → 噪点 → 暗角。共 ≤5 层，GUI 渲染压力可控。

### 1.6 动画原则

所有「活着的感觉」用 **sin 波 + 帧计数**驱动，禁止硬编码帧序列（省内存、无素材）。

| 动作 | 驱动 | 参数 |
|---|---|---|
| 玩家呼吸（idle） | `scaleY = 1 + 0.03*sin(t*2)` | 周期 ≈ π s |
| 玩家走路 bob | `yOffset = -1.5*abs(sin(t*10))` | 同步移动速度 |
| 苍蝇振翅 | 翅角度 `±25° * sin(t*40)` | 高频 |
| 蜘蛛腿抖 | 每条腿相位偏移 `sin(t*8 + i)` | 相位错开 |
| 眼泪尾迹 | 后置 2–3 个渐隐小圆，间距随时间 | 视觉速度感 |
| **命中闪白** | 受击后 `12–15 帧` 内，整体轮廓用 `globalCompositeOperation='source-atop'` 叠白，或绘制时 `filter` 不可用时直接改填充为白 | 时长 ~0.2s |
| **无敌闪烁** | 受伤后 60 帧，每 6 帧切换 `globalAlpha 1 ↔ 0.35` | 0.5–0.6s 无敌 |
| **死亡爆散** | 粒子系统：8–14 个血色圆 + 3–5 个肉块，初速 2–4 px/帧，重力 +0.15，寿命 30–45 帧 | 可加屏幕震动 |
| 门开/关 | 门扇宽度 `lerp` 动画 8 帧 | — |
| Boss 张嘴预告 | 嘴张开度 `0→1` 用 18–24 帧缓动（easeOut），停 10 帧，再发射 | 给玩家反应窗口 |

**原则**：预告动作（telegraph）**必须 ≥ 18 帧**且形状变化明显（张嘴/眼睛发光），否则玩家无法反应 —— 这既是手感也是可访问性要求。

### 1.7 UI 视觉

- **HUD 心形**：见 §2.7 配方。心排布在左上角，每行 6 个，行距 16px。
- **道具栏**：左上/顶部一排 16×16 图标格，间距 4px，底衬 `C_UI_BG` 圆角矩形 + `C_UI_GOLD` 1px 边框。
- **字体**：
  - 首选 `monospace` 或 `"Courier New"`（复古打字机感），fallback 系统 sans。
  - 所有文字**硬描边**制造可读性 + 风格：
    ```js
    ctx.font = 'bold 16px "Courier New", monospace';
    ctx.textAlign = 'center'; ctx.textBaseline = 'middle';
    ctx.lineWidth = 3; ctx.strokeStyle = C_TEXT_SHADOW; ctx.strokeText(s, x, y);
    ctx.fillStyle = C_TEXT; ctx.fillText(s, x, y);
    ```
  - 数字（血量/金币/钥匙/炸弹）：`C_UI_GOLD` + `C_TEXT_SHADOW` 描边，右对齐图标。
- **最小字号**：正文 14px，数字 16px（见 §1.8）。

### 1.8 可访问性（美术侧）

- **对比度**：正文/关键 UI 与底色对比度 ≥ **4.5:1**；血条/心形等生命指示 ≥ **3:1**。`C_TEXT #f0e6d8` on `C_UI_BG #1b1210` ≈ 12:1 ✅。
- **不靠颜色单通道传递信息**：
  - 心形血量：红心/空心/半心**形状本身不同**（实心 vs 轮廓 vs 半填充），色盲友好。
  - 敌人伤害预告：**形状变化（张嘴）** 而非仅变红。
  - 子弹类型：**形状差异**（圆泪/长刀/激光条）而非仅颜色。
- **色盲安全替代色**：提供高对比模式，把红→橙红 `#ff7a3c`、绿→青 `#2fd4c8` 分离红绿色域（见 accessibility.md）。
- **屏幕震动/闪白开关**：所有 `translate` 震动与白闪必须有「减弱/关闭」选项，震幅默认 ≤6px（见 §3）。

### 1.9 禁止事项（风格红线）

1. ❌ **禁止任何外部图片/字体文件**：全部代码绘制 + 系统字体。（**静态站点合规确认见 §3.4**）
2. ❌ **禁止纯黑 `#000000` 描边 / 纯灰大面积填充** —— 必须用暖黑 `#1a0d0d`、暖灰。
3. ❌ **禁止 ≥ 5px 描边的普通角色**（只有 Boss 允许 5–6px）—— 会失手绘感。
4. ❌ **禁止平滑抗锯齿的「矢量卡通」外观**：必须带有机抖动/噪点，否则风格变廉价扁平。
5. ❌ **禁止渐变换色用彩虹色**：每个渐变只走同色系明暗（±20% 明度）。
6. ❌ **禁止动画用硬编码帧序列**：统一 sin 波/缓动驱动，保持代码可调。
7. ❌ **禁止在每帧循环里 `createRadialGradient` 重建重物体**：静态层一律预烘焙。
8. ❌ **禁止去掉「怪诞可爱」的可爱面**：可以恶心，但轮廓必须圆、比例必须 Q —— 纯恐怖即偏离锚点，打回。

## 2. 代码绘制规格表（核心 · 开发照此编码）

> 约定：坐标以**实体中心为原点 (0,0)**，绘制函数内用 `ctx.save/translate/restore`。
> `OX/OY` = 相对中心的偏移。所有尺寸为**默认 1× 缩放**下的 px。
> 描边默认 `ctx.lineJoin='round'; ctx.lineCap='round';`。

### 2.1 玩家：以撒（Isaac）

**整体尺寸**：宽 ≈ 24px，高 ≈ 32px（含头）。命中盒 ≈ 24×26（脚部留空）。

**图层顺序（正面朝向）**：
1. 阴影椭圆（`rgba(0,0,0,0.3)`，rx=11, ry=4，OY=+16）
2. **腿** ×2：两个小圆角矩形 `w6×h8`，OX=∓5, OY=+11；填充 `C_DARK_CLOTH`，描边 3.5px `C_BODY_LINE`
3. **身体**：梨形。用 `bezierCurveTo` 从 (OX-9,OY-2) 到 (OX+9,OY+8) 收口。填充 `C_DARK_CLOTH`

5. **头**：圆，r=12，OY=-10。填充 `C_SKIN` → 叠一层 `createRadialGradient`（左上亮 `C_SKIN` → 右下 `C_SKIN_SHADE`）

9. **描边**：头 + 身体 + 腿统一 3.5px `C_BODY_LINE`
10. **受伤覆层**：闪白帧时，用第 11 步叠加

**四种朝向**：
- **下（正面）**：如上。
- **上（背面）**：不画眼睛/嘴；后脑勺加一撮呆毛（2×3px 三角）。
- **左/右**：眼睛只画 1 只（近侧），另一侧被头缘遮；嘴偏移到侧面；身体略窄（宽 ×0.9）。**右 = 左水平镜像**（`ctx.scale(-1,1)`），只需写一套。

**走路 bob**：整体 `OY += -1.5*abs(sin(t*10))`；腿交替 `±3px` 上下。

**受伤状态**（`hpFlash` 帧）：

ctx.globalCompositeOperation = 'source-atop'; // 仅在角色离屏canvas内有效
ctx.fillStyle = C_IMMUNE_FLASH; ctx.fillRect(-16,-20,32,40);
ctx.globalCompositeOperation = 'source-over';

### 2.4 Boss：Monstro 蒙斯特罗（大嘴 blob）

**尺寸**：约 64×58（房间中央巨大）。

**图层顺序**：
1. 阴影椭圆 rx=30 ry=9
2. 主体 blob：不规则大圆/南瓜形，用 6–8 个 `bezierCurveTo` 控制点构成微凹凸轮廓。填充 `createRadialGradient(左上 → 右下)`：`C_MONSTRO_HI` → `C_MONSTRO_BODY`
3. 主体描边 6px `C_BODY_LINE`（Boss 级重线）
4. **嘴（关键）**：占脸部下半 60% 的巨口
   - 张开度 `open ∈ [0,1]` 控制上下唇距离：`mouthH = lerp(6, 26, open)`
   - 上唇/下唇：2 条粗 `bezierCurveTo` 弧，填充 `C_MONSTRO_MOUTH`
   - 牙齿：上下各 5–7 颗 `C_TOOTH` 三角，尖朝内
   - 口腔深处：`C_MONSTRO_MOUTH` 上叠更暗 `#3a0a14` 椭圆
5. 眼睛 ×2：位于嘴上方两侧，白/黄眼球 `#f2e6d0` r=6 + `C_EYE` 瞳孔 r=3；**瞳孔随玩家位置偏移**（追踪感）
6. 眉/皱纹：2 条 `C_BODY_LINE_2` 粗弧，怒相
7. 皮肤斑点：4–6 个 `C_MONSTRO_HI` alpha 0.4 小椭圆（脏污感）
8. 描边（嘴、眼）3px

**分阶段外观**：
- **阶段 1（HP 100–66%）**：正常，眼白黄，嘴微张。
- **阶段 2（HP 66–33%）**：眼睛变红（瞳孔 `C_BRIMSTONE`），身上加 2 条血痕，主体色调偏移（叠 `rgba(200,18,42,0.12)`）。
- **阶段 3（HP 33–0%）**：眼中喷血线，嘴常半张，主体抖动 `±1px` 每帧（濒死狂暴），描边略抖。

**张嘴预告（攻击前）**：
1. 帧 0–20：`open: 0 → 1`（easeOut），眼睛瞪大（r×1.2）
2. 帧 20–30：保持张嘴（视觉威胁）
3. 帧 30：发射弹幕/冲刺
4. 帧 30–45：`open: 1 → 0`
> **预告亮度**：张嘴瞬间嘴内可闪一下 `C_BRIMSTONE_HI`（1–2 帧），呼应可访问性「形状+亮度双通道预告」。

**跳跃**：整体 `OY` 用抛体曲线，落地帧触发屏幕震动 + 尘埃粒子（8 个 `C_WALL_TRIM` 灰点）。

## 3. 渲染性能指引（Canvas 2D 关键优化）

### 3.1 预烘焙（离屏 canvas，一次性）vs 每帧实时绘制

| 内容 | 策略 | 原因 |
|---|---|---|
| 地砖 | **预烘焙整间**（一次性画满房间地砖到 1 张 offscreen，每帧只 `drawImage` 1 次） | 数百格每帧重绘 = 巨量 fillRect |
| 墙（4 边） | **预烘焙** | 静态 |
| 噪点脏污层 | **预烘焙且与地板合并** | 数万个点，绝不能每帧画 |
| 暗角渐变 | **预烘焙**（房间尺寸变化时重建） | `createRadialGradient` 不易每帧建 |
| 道具图标 | **预烘焙 atlas**（启动时烘焙 N 个 16×16） | 图标小、数量多、静态 |
| 岩石/坑洞/尖刺/宝箱/基座 | **预烘焙独立 sprite**，运行时 `drawImage` 到房间坐标 | 静态结构物 |
| 玩家/敌人 | **每帧实时绘制**（但可缓存各朝向基础层） | 姿态/朝向/受伤态频繁变化 |
| 子弹/粒子 | 每帧实时绘制（粒子可对象池） | 动态 + 数量中等 |
| HUD 心/图标 | 每帧 `drawImage`（心形可预烘焙满/半/空 3 张） | 数量少，但形状复杂 |
| 文字 | 每帧 fillText（避免缓存文本位图，便于缩放/可访问性） | 数目少 |

**缓存键建议**：玩家基础层可按 `facing` 缓存 4 张；敌人按「类型+朝向」缓存。**仅当角色上限多且性能不足时**再引入缓存，优先保持代码简单。

#### 3.1.1 每帧绘制调用量级估算（供性能预算核对）

> 场景口径：单房间，最坏情况 = 5 敌人（含 Fly 蜂群则 6）+ 满屏弹幕（GDD 上限 80）+ 粒子峰值。
> 「调用」= 一次 `fill/stroke/drawImage`。估算基于 §2 各配方实际图元数。

| 类别 | 数量上限 | 单次绘制调用 | 小计 | 策略 |
|---|---|---|---|---|
| 地板 | 1 | 1 drawImage | **1** | 预烘焙整间 |
| 墙（4 边+角） | 1 | 1 drawImage | **1** | 预烘焙 |
| 暗角 | 1 | 1 fillRect | **1** | 预烘焙 |
| 静物（岩石/坑/尖刺/宝箱/基座） | ~15 | 1 drawImage/个 | **≤15** | 预烘焙 sprite |
| 玩家以撒 | 1 | ~14（阴影+腿2+身+臂2+头+眼2+嘴+描边；每附加物 +1~4） | **≤25**（满道具时） | 实时 |
| 普通敌人（Gaper 类） | 5 | ~12 | **≤60** | 实时 |
| Fly 蜂群 | 6 | ~5 | **≤30** | 实时 |
| Monstro Boss | 1 | ~35（blob+嘴+牙6+眼+光斑+描边） | **35** | 实时 |
| 子弹/眼泪 | 80 | ~3（外圈+核心+高光）；激光 1 | **≤240** | 实时 + 对象池 |
| 粒子（死亡爆散） | 40 | 1 drawImage/个 | **≤40** | 预烘焙圆点 + 对象池 |
| HUD（心 6～12 + 道具栏 ≤18 + 数字） | ~40 | 1 drawImage/个 | **≤40** | 心预烘焙 3 张 + 图标 atlas |
| 文字 | ~6 | 2（stroke+fill）×6 | **≤12** | 实时 |

**峰值合计 ≈ 500 次绘制调用/帧**（60Hz → ~30k 次/秒）。

**结论与预算判定**：
- 纯矢量绘制下 500 calls/帧在 Canvas 2D 属**安全区**（现代浏览器 60Hz 可稳定承受 ~1000–2000 简单调用）。
- **最大风险点是 80 发子弹 × 3 调用 = 240**。缓解：子弹**预烘焙成 4 张 sprite**（基础泪/大泪/刀/绿弹），运行时 `drawImage` 从 3 调用降到 1；激光保持实时（每帧仅 2–3 条）。
- 若加预烘焙子弹后，峰值 ≈ **320 calls/帧**，余量充足。
- **建议**：开发先按「实时绘制」实现并实测；若帧率 < 58fps，按此优先级优化 —— ①子弹 sprite 化 ②敌人朝向缓存 ③粒子 `drawImage` 替代 `arc`。

### 3.2 屏幕震动 / 闪白 实现建议

**屏幕震动**：
```js
// 全局偏移，在渲染最外层 ctx.translate 前应用
const shakeAmp = Math.max(0, shakeT / SHAKE_MAX) * MAX_AMP; // MAX_AMP 默认 6px
const ox = (Math.random()*2-1) * shakeAmp;
const oy = (Math.random()*2-1) * shakeAmp;
ctx.save(); ctx.translate(ox, oy);
// ... draw world ...
ctx.restore();
```
- 触发点：Boss 落地、玩家受伤、爆炸。震幅 ≤ 6px（**可访问性上限**），时长 8–14 帧。
- **必须受「震动开关」控制**：关闭时 `MAX_AMP=0`；减弱时 `MAX_AMP=2`。
- 可对震动做**整数取整** `Math.round` 以免亚像素模糊。

**闪白（全局白闪）**：
```js
ctx.fillStyle = `rgba(255,255,255,${flashA})`; // flashA 从 0.6 衰减到 0
ctx.fillRect(0, 0, W, H);
```
- 用于 Boss 死亡、受击反馈。**必须受「闪烁/强光开关」控制**：可关闭或用降低 alpha 的替代（如仅角色闪白，不做全屏）。
- ⚠️ 全屏高频闪烁是光敏性癫痫风险 —— 本作**限制全屏白闪频率 ≤ 3 次/秒且 alpha ≤ 0.6**，且默认提供关闭。

### 3.3 整数像素对齐 & 抗锯齿

- **DPR 处理**：`canvas.width = cssW * dpr`，`ctx.scale(dpr, dpr)`，让绘制逻辑按 CSS px 思考。
- **`ctx.imageSmoothingEnabled`**：
  - 绘制**预烘焙 sprite 缩放**时：`false`（保持像素锐利、复古感）。
  - 绘制**渐变/角色每帧**时：`true`（形体边缘平滑）。
  - 建议：默认 `true`，仅在地砖/sprite 图集缩放时临时 `false` 并在用后还原。
- **整数对齐**：静态结构（墙/地砖/门）坐标取整 `Math.round`，避免接缝亚像素亮线；动态实体可保留小数以获得平滑运动。
- **避免 `ctx.save/restore` 滥用**：深层嵌套 save/restore 有开销；绘制循环内尽量限制层级 ≤ 4。
- **避免每帧 `create*Gradient`**：能预烘焙的渐变一律预烘焙（暗角、眼泪渐变等小对象可接受，但大的要缓存）。
- **对象池**：粒子/子弹用固定大小池 + `alive` 标记，避免 GC 抖动。

### 3.4 静态站点合规确认（外部资源零依赖）

> 项目为**纯静态站点**（后续 `python -m http.server` 直接跑 + 发布上线），**不得依赖任何外部图片/字体文件**。

**逐项审计结果**：

| 资源类型 | 是否需要外部文件 | 本作方案 | 判定 |
|---|---|---|---|
| 角色/敌人/Boss 图形 | ❌ 不需要 | Canvas 图元路径实时绘制 | ✅ 纯代码 |
| 地砖/墙/道具图标/心形/HUD | ❌ 不需要 | 启动时烘焙到**内存离屏 canvas**（`document.createElement('canvas')`），非磁盘文件 | ✅ 纯代码 |
| 噪点/脏污纹理 | ❌ 不需要 | `ImageData` 随机点程序生成 | ✅ 纯代码 |
| 字体 | ❌ 不需要外部字体文件 | **系统字体栈**：`'Courier New', Consolas, monospace`；中文 fallback `system-ui, sans-serif`。**禁止 `@font-face` 引外部 woff/ttf** | ✅ 系统字体 |
| 图标（道具栏） | ❌ 不需要 | 16×16 图元配方 + 离屏 canvas atlas（§2.6） | ✅ 纯代码 |
| 音频 | ➖ 本作无音频资源 | （若未来加音效→ `WebAudio` 程序合成，同样零文件） | ✅ 合规 |

**结论**：**全部配方均为纯代码，零外部资源依赖。** 页面只需 1 个 `.html` + `.js` + `.css`，`http.server` 可直接服务，无 CORS/资源加载问题。

**开发注意**：
- 不要把「预烘焙」误解为「预生成图片文件」—— 是**运行时内存 canvas**。
- 图标若要「图集」形式，也是一张内存 canvas 上用 `drawImage(src, sx,sy,sw,sh, dx,dy,dw,dh)` 切片，不落地成 PNG。
- 字体若视觉效果不足，**不得**引入外部字体，只能调整字号/字重/描边粗细。

## 4. 落地建议（给开发的接入顺序）

1. **先实现 `palette.js`**（§1.2 全部色值常量）—— 全项目唯一色源。

   `地板(烘焙) → 墙(烘焙) → 基座/岩石/坑/尖刺(烘焙 sprite) → 暗角(烘焙) → 阴影 → 敌人 → 玩家 → 子弹 → 粒子 → 暗角叠加 → HUD → 全局白闪/文字`。
5. **命名规范**：绘制函数 `draw<Category>_<Name>`；常量 `C_*`；预烘焙资源 `bake*`；每实体附带 `HITBOX` 常量。
