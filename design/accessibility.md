## 1. 分级体系定义

采用四级模型（本作在三级内选定目标）：

| 级别 | 定义 | 典型成本 |
|---|---|---|
| **Basic** | 满足最低可用性：可暂停、可调音量/静音、基本对比度。 | 低 |
| **Standard** | 覆盖主流无障碍需求：色盲模式、文本可读性、按键重映射、震动/闪烁开关。 | 中 |
| **Comprehensive** | 覆盖边缘需求：完整 remap、屏幕阅读器语义、认知辅助、难度辅助选项、无闪烁保证。 | 高 |
| **Exemplary** | 行业标杆级，含辅助模式全流程、专家咨询、自动化测试。 | 极高 |

## 2. 本作选定级别：**Standard（含一项 Comprehensive 加配）**

### 选定理由

1. **游戏类型特性**：以撒是**高速动作 roguelike**，弹幕（眼泪、血激光）与敌人攻击**高度依赖视觉反应**。这是可访问性难度最高的类型之一 —— 单靠「给个开关」不够，必须保证**信息冗余通道**（形状 + 亮度 + 音效提示，而非仅颜色）。
2. **网页原生优势**：Canvas 2D + JS 让「文本缩放、按键重映射、开关」实现成本低，无引擎限制，因此**不选 Basic 是浪费**。
3. **零依赖约束**：无法引入第三方 a11y 库，屏幕阅读器/完整语义树成本高，且游戏核心是实时 Canvas 画面（屏幕阅读器对动作游戏支持本就有限）——因此**不选 Comprehensive 全量**，避免过度工程。
4. **PASS 优先级**：色盲模式 + 高对比 + 震动开关 + 闪烁开关 + 按键重映射 + 暂停 + 文本缩放 —— 这 7 项是本作的**核心可访问性契约**，必须全部达成。
5. **加配项（Comprehensive 级）**：**「降低弹幕密度/速度」辅助模式**（accessibility assist）—— 因为弹幕是最大障碍，本作额外提供，作为本作唯一 Comprehensive 特性。（可选：若时间允许加「自动瞄准辅助」。）

## 4. 色盲安全方案（关键设计）

**原则：任何依赖颜色区分的游戏信息，必须有形状/亮度冗余通道。**

| 信息 | 原始通道 | 色盲冗余通道 |
|---|---|---|
| 生命（红心） | 红色填充 | 满=实心 / 半=半填充+分隔线 / 空=轮廓 —— **形状即状态** |
| 魂/黑心 | 蓝/黑 | 蓝色配白心形轮廓，黑色配紫描边 —— 描边色不同 |
| 子弹类型 | 颜色 | 泪=圆 / 刀=长条 / 激光=细线 / 吐弹=绿块 —— **形状完全不同** |
| 敌人伤害预告 | 变红 | **张嘴/缩放**（art-bible §2.4）—— 形状变化优先 |
| 危险区域（尖刺/坑） | 颜色偏暗 | 尖刺=尖锐三角轮廓 / 坑=纯黑+高光边 —— 轮廓区分 |
| 可拾取物 | 金色 | 光晕呼吸 + 浮动动画 —— 运动通道 |
| 门状态 | 颜色 | 开=露黑洞 / 关=有门扇 / 锁=金锁形 —— 形状区分 |

**三套色盲调色板**（在 art-bible `C_*` 之上做覆盖）：

| 语义 | 默认 | Protanopia | Deuteranopia | Tritanopia |
|---|---|---|---|---|
| 血/伤害 | `#c8122a` | `#e67300`（橙） | `#e67300`（橙） | `#c8122a`（红保留） |
| 毒/绿 | `#7a8a4a` | `#4a6ad1`（蓝） | `#2f8fd1`（蓝） | `#8a6a3a`（棕） |
| 魂心 | `#4fa3d1` | `#2f8fd1` | `#2f8fd1` | `#8a8fd1`（紫蓝） |
| 金 UI | `#f2c14e` | `#f2c14e`（保留） | `#f2c14e`（保留） | `#f2c14e`（保留） |

> 实现：调色板以 `PALETTE` 对象全局注入，切换模式只替换被覆盖的少数 key，不影响结构。

## 5. 文字可读性规范

- 正文最小 **14px**，默认 16px；UI 数字 16px。
- 所有文字带 2–3px 硬描边（art-bible §1.7），保证在任何底色上可读。
- 三档缩放：小 14 / 中 16 / 大 20（行高 = 字号 ×1.4）。
- 字体优先 `"Courier New", monospace`（复古 + 等宽易读），fallback 系统 sans-serif。
- 关键数字（HP/金币）大号 + 金色 + 黑描边。
- 对比度：正文 ≥ 4.5:1，生命指示 ≥ 3:1（默认 `C_TEXT #f0e6d8` on `C_UI_BG #1b1210` ≈ 12:1 ✅）。

## 6. CONCERNS 明细

| 项 | 问题 | 影响 | 缓解 / 建议 |
|---|---|---|---|
| **手柄支持** | 需实现 Gamepad API 轮询 + 死区 + 按键映射 UI | 部分玩家无法用手柄 | v1 保留键盘为主；Gamepad 列为 **v1.1**；架构上输入层做抽象 `InputSource` 接口，便于后续接入 |
| **屏幕阅读器** | 实时 Canvas 画面无 DOM 语义树 | 视障玩家难以游玩动作核心 | 菜单/设置等 UI 层用真实 DOM + ARIA 标签（可朗读）；游戏主画面不可朗读（本类型客观限制）——**标注为已知限制**，不阻塞发布 |
| **认知辅助** | roguelike 核心难度不可无损降低 | 反应/认知受限玩家门槛高 | 提供「辅助模式」（弹幕 ×0.7 速度 + 预告帧 +30%）；不改变核心数值平衡，仅降速 |
| **光敏风险** | Boss 死亡全屏白闪 | 光敏性癫痫风险 | 已通过「闪烁开关」默认关闭全屏白闪 + 频率/强度上限约束（art-bible §3.2）→ 风险**已缓解**，判定为 PASS |
| **颜色依赖残余** | 部分敌人在极暗环境下辨识度低 | 高对比模式下改善 | 高对比模式可提升轮廓对比；建议开发实测极端画面 |

## 7. 总判定

**选定级别：Standard（+ 1 项 Comprehensive 加配）**

| 契约项 | 判定 |
|---|---|
| 暂停 | ✅ PASS |
| 音量/静音 | ✅ PASS |
| 色盲模式（3 套 + 形状冗余） | ✅ PASS |
| 高对比模式 | ✅ PASS |
| 屏幕震动开关 | ✅ PASS |
| 闪烁/无闪烁开关 | ✅ PASS |
| 文字大小三档 | ✅ PASS |
| 按键重映射 | ✅ PASS |
| 音效视觉提示 | ✅ PASS |
| 弹幕减速辅助（加配） | ✅ PASS |
| 手柄支持 | ⚠️ CONCERNS（v1.1） |
| 屏幕阅读器语义 | ⚠️ CONCERNS（已知限制，菜单层 ARIA） |
| 完整认知辅助 | ⚠️ CONCERNS（提供减速辅助替代） |

**结论**：本作在 Standard 级全部 10 项核心契约**达成 PASS**；3 项 Comprehensive 级特性中 1 项加配达成（弹幕减速）、2 项标注 CONCERNS 并给出缓解路径，**不阻塞 v1 发布**。
